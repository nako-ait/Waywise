# Waywise

> 一句话说清楚去哪、几天、怎么玩 → AI 把地点标到地图上 → **先给你看方案、你确认** → 求解器编译成一份带时间轴、真实路网、可分享可导出的路书。

比赛 / 校招作品，当前版本 **v1.11**。旧版说明见 [docs/README_旧版_v1.0.md](docs/README_旧版_v1.0.md)。

---

## 它能做什么

| 能力 | 说明 |
| --- | --- |
| **一句话规划** | 「带爸妈玩两天，想去朱家角、七宝老街，别太累」→ 解析地点与偏好 |
| **先确认再动手** | 每轮先出提案（加什么、删什么、改什么），点「确认执行」才改路书，并回一行变更小字 |
| **可互动时间轴** | 逐段换交通方式（点一下立刻高亮）、删站点、加地点；合计按每段各自方式计算 |
| **多约束求解** | 营业时间窗、午休、每日起止、5 种交通方式、多日分天；预算/路上时长超限会自动降档，做不到就如实说 |
| **照片探索** | 32 张实景摄影组成动态圆环，悬停打开左侧旅行助手，点击照片载入推荐路线并进入工作台 |
| **十五城可选** | 上海 / 北京 / 杭州 / 成都 / 西安 / 广州 / 苏州 / 大理 / 敦煌 / 厦门 / 黄山 / 青岛 / 重庆 / 张家界 / 大同 |
| **分享与导出** | 6 位口令分享（导入端重算）、导出 1080 宽长图 |
| **没有 Key 也能跑** | 无 LLM Key 自动降级规则解析；无高德 Key 用离线估算，界面标注数据来源 |

## 快速开始

后端（Python 3.11+）：

    cd backend
    .venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

前端（Node 18+）：

    cd frontend
    pnpm install
    node node_modules\vite\bin\vite.js

打开 <http://127.0.0.1:5173>。Windows 下也可直接双击仓库根目录的 `启动.bat`。

Waywise 首页、推荐路线素材、兼容性与验证说明见 [docs/WAYWISE_UI.md](docs/WAYWISE_UI.md)。

前端默认走**同源 /api**（Vite 代理到 8000），不会有跨域问题；要直连可设 `VITE_API_BASE`。

### 密钥怎么配

两把高德 Key 不是同一把，别混用：

| Key | 放哪 | 用途 |
| --- | --- | --- |
| 高德 **Web 端 (JS API)** Key + 安全密钥 | `frontend/.env.local` | 地图显示、前端路径规划 |
| 高德 **Web 服务** Key | 「个人」页填写，或 `backend/.env` 的 AMAP_WEB_KEY | 后端距离矩阵、真实路网、地理编码 |
| 大模型 Key（DeepSeek / 通义 / 智谱） | 「个人」页填写，或 `backend/.env` | 对话提案、地点解析、解释 |

「个人」页填的 Key 随请求头（x-llm-key / x-amap-key）传给后端，只存在本地浏览器，不落盘、不入库。
填完点 **「测试 AI 连接」**，显示 ✅ 才算真的通。

## 架构

    frontend (React + Vite + Zustand)
      ├─ 首页       城市选择 / 悬浮推荐气泡 / 底部一句话输入
      ├─ 工作台     左：AI 对话（提案 → 确认 → 变更回执）｜中：地图｜右：出发酒店 + 可互动时间轴
      ├─ 详情/分享   只读路书 + 导出长图
      └─ 个人       本地账号 / 密钥 / 路线库 / 分享记录

    backend (FastAPI)
      ├─ /api/plan         求解器：距离矩阵 → TSP/VRP → 时间轴（OR-Tools 可选，缺省纯 Python）
      ├─ /api/ai/turn      一句话 → 提案（LangGraph 状态机：understand → propose → guard）
      ├─ /api/ai/apply     确认后执行：合并参数 → 重算 → 变更回执
      ├─ /api/ai/parse|replan|explain    解析 / 重规划 / 解释
      ├─ /api/share        6 位口令分享
      └─ SQLite 缓存       距离矩阵与分段路径（默认 168 小时）

**设计取舍**：模型负责「听懂 + 选点 + 调参 + 解释」，**排程交给确定性求解器**——
这样时间窗、往返闭环、费用不会被模型编出来的时间骗到。

### 对话状态机（LangGraph）

    understand ──► propose ──► guard ──► END
       │              │           │
       │              │           └─ 事实校验：没有数据的字段（酒店星级/房价/天气/门票）
       │              │              一律降级成「我没有这项数据 + 替代方案」
       │              └─ 模型出 ops（加/删点、天数、方式、权重、预算/时长上限）
       └─ 没 Key/超时 → 规则兜底

## 已知边界（不吹）

- **账号是本地账号**：昵称/密钥/路线库存在浏览器 localStorage，没有服务端登录与跨设备同步。
- **数据范围**：上海有 276 个真实 POI 快照；其它城市是内置地标（演示用），真实搜索需配高德 Web 服务 Key。
- **没有的数据**：酒店星级/实时房价、天气、实时人流、门票与人均消费——问到时会明确说没有，不编造。
- **约束是「尽量满足」**：预算/时长上限会触发自动降档或提示，极端不可行时如实告知，而不是硬解。
- **移动端**未适配（桌面宽度设计）。
