# 交通选择与提案试算修复

问题：用户要求合理安排、少走路时，AI 可能自行提出“全程公交”，且预览沿用旧权重，说明中的时间也未受完整往返统计约束。

此次调整：

- 自动乘车路段比较公共交通和打车，短途同时比较步行；逐段手动方式保持优先，自驾不自动换打车。
- 未明确提出交通方式时，提案不新增整体方式；整体方式的文案改成交通偏好。
- 预览和执行共用 `agent.request_from_ops`，统一权重、时间、原有目的地、营业时间及逐段覆盖的合并规则。
- 提案数字由程序按每段实际交通及每天返程累加，展示时间、接驳步行、费用、换乘、估算状态和未排入地点。
- 对比按偏好自动选择与公共交通方案；自动方案全为公共交通时，增加一段打车对照。相同结果去重，存在费用取舍时直接列明。
- 确认执行不再为满足上限清空手动选择并暗中切换整体方式；未满足的上限明确提示。
- AI 新增地点的营业时间和标签也保留到前端，避免后续重算丢失。

对照范围：一段打车对照选取公共交通耗时最长且未被手动锁定的路段，不穷举所有混合交通组合。确认按钮生成按当前偏好选择的方案，对照用于展示取舍。路线顺序仍由现有矩阵求解器确定，不能宣称整个行程全局最优。

验证：完整离线回归 6/6 套件通过；交通提案新增 10 项检查通过；前端类型检查与生产构建通过。另用项目配置的高德接口试算上海大学宝山校区往返外滩、陆家嘴滨江大道，验证对照结果来自实际交通段并包含返程。

运行：后端源码改动需重启后端；页面旧对话不会自动重写，需重新提交需求查看新提案。

## 打车数据修复

滨江大道至外滩原显示约53.7分钟、11.97公里、40.23元。复查发现原始景观坐标被驾车接口匹配到绿道，造成向南绕行；费用则来自固定里程公式。

- 驾车请求附带已知景点的 POI 标识，使用推荐策略和完整响应，让服务匹配车辆到达点。排序矩阵也查询并使用入口/出口坐标，目的地本身的位置保留。
- 打车费用优先取高德 `taxi_cost`，标为出租车估算；缺失时明确标注本地估算。自驾成本补计接口道路收费。
- 驾车路线和矩阵采用新版本缓存键，旧异常数据不再命中；缓存有效期缩短为5分钟，保留查询时间及命中状态。
- 接驳步行按车辆路线端点到景点的偏移估算并计入总时长，不再用驾车路程的固定比例。
- 网页改为显示“高德路线”、估算费用及查询时刻，移除“起步价16元”等固定文案。旧路书或过期车辆数据在工作台打开时核算一次，并提供“重新核算交通”。
- 2026-10-28本次接口验证：该方向约5.99公里，行驶27.1分钟、接驳约1.1分钟，合计约28.2分钟，出租车估算21元。数值是查询时参考，不包含叫车等待，不是网约车平台报价。

验证：7/7离线套件通过，其中10项新增打车数据检查；前端类型检查和构建通过；完整规划接口额外验证了费用来源、返回段及总统计一致。

## 路线偏好与交通重选

逐段手动指定仍是明确约束，普通重新编译会保留。路线偏好面板新增“按偏好重选交通”：清除逐段指定后按当前权重重新比较，同时提供“保留指定交通重算”。时间轴每段可单独点“自动”，整体“恢复自动”也可清除指定。

恢复自动会用公共交通作为排序基准，避免旧步行矩阵提前丢弃可乘车到达的点；自驾仍保持车辆连续性。短于20分钟的自动步行路段也会比较乘车方案，响应时间、费用等偏好。计算过程中设置再次变化时，旧结果不会覆盖当前设置。偏好改变后若综合评分仍选同一方式，保留原方式是正常结果。

少走路权重为0时，全天建议步行量只提示，不再强制换成更贵的交通，避免覆盖纯费用/时间偏好。
