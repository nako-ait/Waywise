# 1.9 改动说明（v1.9）：先确认再动手 + 变更回执

## 一、交互契约变了

以前：你说一句 → 直接改路书、直接重算。
现在：你说一句 → AI 只出**提案**（准备改什么）→ 你点「确认执行」→ 才真正改参数并编译。

```
我：把外滩去掉
AI：收到，去掉外滩。确认后我再改动。
    ┌ 准备这样改 ────────┐
    │ · 去掉 外滩         │
    └────────────────────┘
    [确认执行] [换个说法]
（确认后）
    ✓ －1 地点 · 已重新编译
```

## 二、变更回执（很小的字）

每次执行完，气泡下面会出现一行 10px 灰字：
`✓ ＋2 地点 · 更新 3 段交通 · 偏好已更新 · 已重新编译`

由后端 `/api/ai/apply` 计算（对比执行前后），不是模型编的。

## 三、能回答「我做不到」

命中"酒店星级/房价、天气、实时人流、门票人均"时会明确说没有这项数据，并给替代动作：

> 我这边没有酒店的星级和实时房价，只有地点本身。把酒店名或地址告诉我，我设成起点；或者你在右侧「出发酒店 → 更换」里搜一下。

## 四、回复变短

- 提案回复 ≤ 2 句（后端 `_short()` 截断到 90 字）；
- 细节放进「准备这样改」的列表；
- 不再罗列参数名。

## 五、接口

| 接口 | 作用 |
| --- | --- |
| `POST /api/ai/turn` | 只出提案：`kind`(act/clarify/answer) + `reply` + `preview` + `ops` |
| `POST /api/ai/apply` | 确认后执行：返回 `plan` + `changes` + `caption` |

## 六、没做完的部分（诚实说明）

1. **LangGraph 没有装**：`backend/.venv` 是 `--without-pip` 建的，`python -m pip` 不可用；跨 HTTP 的 `interrupt` 需要 checkpointer 持久化，收益不抵风险。本版用**显式状态机**（turn → apply）实现了同样的语义，接口形态与 LangGraph 的 interrupt 对齐，后续可平滑替换。
2. **提案仍是规则驱动**：`agent.build_proposal()` 用关键词 + 本地 POI 检索，没走大模型；加入对话历史、工具循环（search_pois / search_hotels / plan）是下一阶段。
3. **没有酒店数据源**：边界话术已就位，但"真推荐酒店"需要新增酒店检索（高德 POI 或演示数据）。
4. 第一轮的"地图立刻标点"改成"确认后标点"——因为确认前不应该动任何状态。

## 七、验收

```
/api/ai/turn  "帮我推荐几个地方，两天" → act + addPlaces + 短回复
/api/ai/turn  "不想去外滩了"           → act + removeNames:["外滩"]
/api/ai/turn  "推荐几家四星酒店，500以内" → answer + 边界话术
/api/ai/turn  "都改地铁吧"             → act + mode:"subway"
/api/ai/turn  "嗯……"                  → clarify + 4 个可点选项
/api/ai/apply 去掉外滩                 → caption "－1 地点 · 已重新编译"
verify_all 4/4 PASS，tsc 0 error
```
