# 1.6 改动说明（v1.6）：AI 回复改成人话

## 问题

之前的对话气泡长这样：

```
权重「convenience」→ 0.9；权重「walking」→ 1.0；交通方式 → 地铁。
已按新参数重新编译：1 天 / 5 站。
```

两个毛病：

1. 这**不是模型的回复**，是前端把后端 `applied`（给程序看的变更清单）原样拼出来的；
   模型只做了"句子 → 参数"这一步，它的措辞被丢掉了。
2. 权重直接用英文 key，用户看不懂；也不解释"为什么是地铁不是打车"。

## 改法

### 1. 后端新增 `reply`

`AiReplanResponse.reply`：一句话人话回复，包含"改了什么 + 为什么 + 现在什么样 + 下一步建议"。

- **有 LLM**：`_compose_reply()` 会再调一次 `call_text`，把「用户原话 + 实际改动 + 用户提到的交通方式 + 编译结果」
  交给模型，要求 2~4 句口语、讲清取舍、不要罗列参数。
- **没 LLM**：用规则拼一段同样人话的回复（离线也有），并按需解释多方式取舍。

### 2. 权重改中文语义

`time→赶时间`、`convenience→少换乘`、`cost→省钱`、`walking→少走路`。
`applied` 也从 `权重「cost」→ 0.4` 改成 `省钱 → 0.4`，同时 `reply` 里会翻成「更看重省钱」。

### 3. 前端

优先展示 `reply`，没有才退回 `applied`；气泡下方标注「大模型 · 已重新编译」或「规则解析 · 已重新编译」。

## 实际输出（无 LLM Key，规则版）

> **你**：尽量坐地铁或者打车
> **AI**：收到，你给了「地铁 / 打车」几个选项，我按更省钱、也不堵车的思路先排了地铁；打车能少走路，但会贵一些。现在这版是 1 天 5 站，步行约 2.92 km，16:11 回到人民广场。如果还想更松一点，可以说「每天少排一个点」或「午饭后回酒店休息」。

> **你**：改成 2 天，6 点前回酒店
> **AI**：收到，这次调整是：收工改到 18:00、天数改成 2 天。现在这版是 2 天 3 站，步行约 2.87 km，12:38 回到人民广场。……

> **你**：不想去豫园了
> **AI**：收到，这次调整是：去掉豫园·城隍庙。现在这版是 1 天 2 站，步行约 0.95 km，12:38 回到人民广场。……

## 为什么"地铁或打车"最后是地铁

求解器的交通方式是**单值**（全行程一个方式），规则解析遇到「地铁或打车」只能选一个，规则里选了先出现的地铁。
`reply` 现在会把这个取舍讲清楚，并给出改口方式（"想全打车就说一句"）。

## 代价与注意

- 有 LLM 时，每一轮多一次文本生成调用（约 1~3 秒，~200 token），换来的是人味和解释。
- 仍要确认 Key 真的生效：个人页「测试 AI 连接」+ 气泡右上角徽标。
- 自检断言已跟着中文标签更新（`少走路`、`省钱`），`verify_all.py` 4/4 通过。
