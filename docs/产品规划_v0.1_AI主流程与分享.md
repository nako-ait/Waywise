## 0. 一句话目标

把「**一句话让 AI 规划整趟行程**」从侧栏里的一个小功能，升级成产品的**主入口**；
并让一份路书可以被**分享出去**、被别人**一键复用**。

---

## 1. 优先级

| 级别 | 内容 | 说明 |
| --- | --- | --- |
| **P0** | AI 主流程（真实大模型） | 这是产品的核心卖点，必须有、必须稳、必须被看见 |
| **P0** | 生成分享（导出） | 没有分享，路书就是本地文件，传播为零 |
| **P0** | 打开别人的分享（导入） | 与分享成对出现，缺一不可 |
| **P1** | 分享短链 + 二维码 | 正式形态，短、可统计、可过期 |
| **P1** | 只读回放页 | 分享落地页，也是"路书详情" |
| **P2** | 导出长图 / 公开路线广场 / 账号体系 / 收藏 | 比赛之后再谈 |

**本期不做**：账号与登录、点赞评论等社交互动、支付、多城市（仍锁定上海）。

## 2. 现状基线（改之前先认清）

**后端已有**：`services/llm.py`（DeepSeek / 通义 / 智谱，OpenAI 兼容，Function Calling）、
`ai_schemas.py`（两个工具 schema + Prompt）、`ai_service.py`（parse / replan / explain 三条链路），
无 Key 时自动降级到 `nlp_rules.py`，且降级路径有测试。

**前端现状**：`AiPanel` 是侧栏第一个面板（三个按钮 + 输入框），**视觉权重很低**，
用户打开页面先看到的是酒店和演示线路，AI 反而像附属功能。

**数据现状**：
- 预置 POI 276 条（本地快照，离线可用）
- 距离矩阵 / 分段路径 → 后端 SQLite 缓存
- 路书只存在浏览器 `localStorage`（`tripcompiler:v1`），**服务端没有任何路书存储**
- 没有任何分享能力（只有地址栏链接，换台机器就没了）

## 3. AI 主流程（P0，重点）

### 3.1 交互形态【已定：AI 必须是主入口】

```
┌─────────────────────────────────────────────┐
│  想去哪、玩几天、怎么玩？一句话说清楚          │  ← 首页 Hero，第一屏
│  [ 带爸妈玩两天，想去朱家角，别太累，住静安寺 ]  │
│                          [ 生成路书 ]        │
└─────────────────────────────────────────────┘
                    ↓ 解析（LLM Function Calling）
┌─────────────────────────────────────────────┐
│  意图卡：地点×3 · 2 天 · 公交 · 少走路 · 9:00-18:00 │  ← 结构化、可改
│  （解析不到的地点会明确列出，不猜）              │
└─────────────────────────────────────────────┘
                    ↓ 编译（现有 planner/solver）
    地图路线 + 竖排时间轴 + 统计 + 「为什么这样排」
                    ↓ 继续对话
    「改成 3 天，用地铁，不去田子坊」 → 增量重算（不是从头再来）
```

**四条必须成立的设计原则**：

1. **AI 的结果必须"可见地结构化"** —— 不是给一段话，而是给一张可编辑的意图卡。
   这是它和"聊天机器人"的分界线，也是答辩最好讲的点。
2. **多轮微调走增量（replan）**，不重新生成整份路书。
3. **AI 只负责"意图 → 参数"，坐标与路径一律不由模型产出**（预置库命中 → 高德地理编码）。
4. **无 Key 也能走完整个流程**（规则解析 + 明示来源），现场断网/没额度不崩。

### 3.2 意图解析契约【建议：把现有两个工具合并成一个 PlanIntent】

现有 `ADD_DESTINATIONS_TOOL`（只解析地点）与 `REPLAN_TOOL`（只解析调整）职责太窄，
建议扩成**一个完整的意图结构**，parse 与 replan 共用同一 schema（`partial` 语义）：

```jsonc
{
  "places":     [{"name": "朱家角", "stayMin": 120, "reason": "亲子"}],
  "exclude":    ["田子坊"],
  "hotel":      {"name": "静安寺", "near": "静安寺"},   // 可空，空则用默认起点
  "days":       2,
  "mode":       "transit",                              // walk|transit|subway|taxi|drive
  "weights":    {"time": 0.6, "convenience": 0.5, "cost": 0.4, "walking": 0.8},
  "dayStartTime":"09:00", "dayEndTime": "18:00", "lunchBreakMin": 60,
  "budgetYuan": null,
  "mustVisit":  ["朱家角"],
  "intentSummary": "带长辈两天、偏轻松、住静安寺"
}
```

规则：
- 模型只填它听懂的字段，其余留空；**留空 = 沿用当前值**（replan 场景）。
- 解析不到坐标的地点 → `unresolved[]` 明示，绝不编坐标。
- `days > 7` 截断、`weights` 归一到 0~1、时间非法则丢弃。

### 3.3 补问（clarify）【待定：要不要做】

当出现以下情况，AI 是**直接挑默认值**还是**反问一句**？

| 情况 | 建议 |
| --- | --- |
| 只说"上海玩两天"，没提地点 | 反问 1 句："偏经典景点还是小众 citywalk？"（给 3 个可点选项） |
| 提及外地城市（如"杭州"） | 明确告知"目前只支持上海"，不静默失败 |
| 地点全部解析不到 | 反问 + 列候选 POI |
| 天数 > 7 / 明显不合理 | 直接截断并提示 |

> 建议**只做 1 轮补问**（不要做成对话机器人），超过就按默认值生成并在意图卡上标"已按默认值"。

### 3.4 降级与可观测【已定】

- LLM 失败（超时 10s / 4xx / 5xx / 返回结构非法）→ 立刻降级规则解析，**不阻塞用户**，UI 标注「规则解析」。
- 每次调用记录：provider、model、latency、tokens、是否降级、失败原因。
  后端写日志；前端有个"调试"开关能看到（答辩时能证明"这不是硬编码"）。
- 意图卡右上角永远显示来源徽标：`大模型` / `规则`。

### 3.5 时延与成本【建议目标】

| 指标 | 目标 |
| --- | --- |
| 一句话 → 意图卡 | < 3s（P50），< 8s（P90） |
| 意图卡 → 路书 | < 1.5s（现有求解器实测 0.1~1.2s） |
| 单次规划 token | < 2k（只传结构化摘要，**不传 polyline**） |

## 4. 分享与复用（P0）

### 4.1 用户故事

- 作为规划者：我排好一份上海两日路书，想发给朋友，"点开就能看、还能直接用"。
- 作为接收者：我打开链接，看到完整路书（地图+时间轴），一键"复制到我的路书"后可以改。
- 作为演示者：答辩现场扫个二维码，评委手机上就能看到这份路书。

### 4.2 三种分享载体【建议：A 先上，B 转正，C 补充】

| 方案 | 做法 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| **A. URL 内嵌** | 把「输入态」序列化 → 压缩 → base64 → 放 hash `/#/s/<payload>` | 零后端改动，当天可上，离线可读 | 链接长（约 1~3KB），丑，无统计/无过期 | **MVP 用这个** |
| **B. 服务端短链** | `POST /api/share` 落库 → 返回 6 位码 `/#/s/ab12cd` | 短、可统计、可过期、可撤回 | 需要存储与接口（约半天） | **正式方案** |
| **C. 文件/长图** | 导出 `.json` 或长图 | 适合发朋友圈/微信 | 不能"点开就用" | P1 补充，**长图是答辩加分项** |

> A 与 B 的落地页可以是同一个：拿到 payload 后走同一套 `SharedTripV1` 渲染。

### 4.3 分享的是什么【建议：分享"输入"，结果只作展示】

```ts
interface SharedTripV1 {
  v: 1
  createdAt: string
  author?: string            // 昵称，可空
  title?: string             // "上海两日 · 亲子"
  hotel: { name: string; lng: number; lat: number; address?: string } | { hidden: true; lng: number; lat: number }
  destinations: DestinationInput[]   // 名称 + 坐标 + 停留 + 营业时间 + 标签
  params: { days: number; mode: TravelMode; weights: Weights; options: PlanOptions }
  order?: string[]           // 原作者编译出的顺序（仅展示/对比，导入端会重算）
  stats?: { walkKm: number; transitMin: number; cost: number }
}
```

**为什么导入端要重算**：路况、求解器版本、本地缓存都会变；重算才能保证"在他机器上也是自洽的"。
`order` 只用于展示"原作者的顺序"，并在导入后做一次对比提示（可选）。

### 4.4 落地页（也是"路书详情页"）【建议布局】

```
┌──────────────────────────────────────────────┐
│ 上海两日 · 亲子        来自 @张三   ·  复制到我的路书 │  ← 顶部条
├──────────────────────────┬───────────────────┤
│                          │  Day 1 / Day 2    │
│        地图（只读）        │  ① 朱家角 09:00-11:30 │
│    路线 + 流动箭头 + 标记   │   ↓ 公交 42 分      │
│                          │  ② 七宝老街 …       │
├──────────────────────────┴───────────────────┤
│ 合计：步行 6.4km · 交通 1h44m · ¥20   [分享][导出长图] │
└──────────────────────────────────────────────┘
```

只读态与编辑态**复用同一套地图/时间轴组件**，只用一个 `readonly` 开关控制交互。

### 4.5 隐私与生命周期【建议默认值】

| 项 | 建议默认 | 备注 |
| --- | --- | --- |
| 酒店名称 | **默认脱敏**为「某酒店（黄浦区）」，可一键公开 | 酒店名会暴露住哪，是隐私 |
| 有效期 | 30 天 | B 方案才需要；A 方案无过期概念 |
| 撤回 | 支持（分享者可删） | B 方案 |
| 口令 | 可选 4 位数字 | 只想发给特定人时用 |
| 访问统计 | 记录 UV/PV | B 方案，答辩可展示"被看过 N 次" |

### 4.6 接口草案【待实现时细化】

```
POST   /api/share            { trip: SharedTripV1, ttlDays?: number } → { code, url, expiresAt }
GET    /api/share/{code}                                              → { trip, views, createdAt }
DELETE /api/share/{code}     （带创建时返回的 deleteToken）
GET    /api/share/{code}/meta  （社交卡片用，P1）
```

服务端存储：SQLite 新表 `shared_trips(code TEXT PK, payload TEXT, created_at, expires_at, views, delete_token)`；
限制：payload ≤ 64KB、创建限流（每 IP 每小时 20 条）、读取不限。

## 5. 前端路由与状态

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | AI 主入口 + 示例 + 最近路书 + 导入分享 |

**store 变更**：
- 新增 `trips: Record<id, Trip>`（本地多份路书，替代现在"只有一份"）
- 新增 `shareState`（分享中/成功/失败）
- `plan` / `planSignature` 保留（属于当前编辑中的 trip）
- 迁移：现有 `tripcompiler:v1` → `trips[default]`，`version: 3`

## 7. 验收标准（可测）

1. **无 Key**：完整走完"输入 → 意图卡 → 路书 → 微调"，全程无红屏，来源标注为「规则解析」。
2. **有 Key**：20 条固定语料（含模糊表达）解析成功率 ≥ 90%，且坐标 100% 来自预置库/高德。
3. **分享**：A 方案的链接在另一台机器/另一个浏览器打开，能完整回放并可导入；导入后编译结果与本地一致（顺序允许因求解器版本微差）。
4. **只读**：分享页所有编辑入口不可用，但地图可拖、可点站点看详情。
5. **性能**：首屏 < 1.5s，规划（含 LLM）P90 < 8s。
