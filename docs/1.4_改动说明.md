# 1.4 改动说明（v1.4）

> 修四件事：逐段选中不高亮（含地图联动）、AI 对话框消失、个人页 Key 不生效（**AI 一直走规则**）。

## 一、逐段选中 / 地图联动

之前"点了不变深色"有两层原因：

1. 高亮读的是**编译结果**里的方式，点了要等后端重算回来才变 → v1.3 已改成读 store 的 `legModes`；
2. **地图上的折线根本没有选中态**（点它只弹信息窗），所以"在地图上选中这段路也不会变色"。

v1.4 补齐：

- store 新增 `selectedLeg`；点地图上任意一段折线 → 该段变**深蓝加粗**，右下信息窗照常弹；
- 右侧时间轴对应那一段同时**浅蓝高亮**；点时间轴里的那一段，地图也会高亮；
- 再点一次取消选中。

## 二、AI 对话框消失

工作台的 AI 框原来塞在左栏底部（固定 300px）。左栏内容一变高（展开酒店、加地点、窗口矮）它就容易被挤出可视区。

v1.4：把 AI 助手改成**悬浮在地图左下角的卡片**（`absolute bottom-3 left-3`，360×300，圆角+阴影），
不再受左栏内容影响，任何窗口高度都在。

## 三、个人页填的 Key 其实没被用上（核心问题）

**原因**：个人页把 Key 存进浏览器 `localStorage`，而**后端只读 `.env`**，两边根本不通。
所以不管填什么，`/api/ai/parse` 都因为没有 Key → 走 `nlp_rules` 规则解析，看起来就是"AI 没有任何智能"。

**修法**（请求级密钥，不改后端配置）：

```
前端 localStorage(profile.llmKey/amapKey)
  → 每个请求带 x-llm-key / x-llm-provider / x-llm-model / x-amap-key
  → FastAPI 中间件写入 contextvars（app/services/keyring.py）
  → llm.current_config() / amap_client._amap_key() 优先用请求里的 Key，没有才回落 .env
```

- 个人页新增**服务商（DeepSeek/通义/智谱）+ 模型**选择和**「测试 AI 连接」**按钮，直接调 `/api/ai/health` 做一次真实探活。
- AI 解析失败时，聊天里会明确写出原因（例如 `⚠️ 大模型解析失败，已降级为规则解析：LlmError: deepseek 返回 HTTP 401 ...`），不再静默降级。

**验证**：带一个假的 Key 请求 `/api/ai/health` → 返回 `configured: true` + `HTTP 401 Authentication Fails`（证明 Key 真的被用了）；
不带 Key → `source=rules`（离线规则）。

## 五、注意

- Key 现在只存在浏览器，请求时随头传给后端，**不落盘**；换浏览器要重新填。
- 若用通义/智谱，记得把「服务商」切过去，模型名按官方填（如 `qwen-plus`、`glm-4-flash`）。
- 高德 Web 服务 Key 生效后，距离矩阵/逐段路径会走真实数据（时间轴会出现「高德实时」徽标），也会开始消耗额度。
