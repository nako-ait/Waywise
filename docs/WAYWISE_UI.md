# Waywise 照片探索首页

## 使用方式

- 首页初始隐藏旅行助手。桌面端的 32 张照片由横排展开为圆环，滚动时依次放大、展开为透视排列；悬停或键盘聚焦照片时从左侧打开助手。
- 点击照片或助手里的「打开这条路线」，会创建新草稿，载入该城市的起点、地点与天数，并调用现有规划接口。保存过的行程、用户资料和历史对话保留；未保存的当前草稿会被新路线替换。
- 助手支持调整推荐路线，也支持选择城市后输入自己的想法。自然语言需求仍经过工作台现有的「提案 → 确认」流程。
- 小屏首页改为照片网格；工作台通过地图、AI 助手、行程三个标签切换。启用系统「减少动态效果」时直接显示最终排布。

## 素材与路线维护

- `frontend/src/data/inspirationCatalog.json`：照片与路线一一对应，包含城市、地点、推荐天数、摄影师和照片原页。
- `frontend/public/inspiration/`：32 张本地 AVIF，共约 1.1 MB，页面不依赖第三方图片服务。`credits.json` 保存素材来源，助手也显示来源链接。素材为 Unsplash 实景摄影，没有生成的景点照片。
- `frontend/src/data/inspirationCities.json` 与 `inspirationLandmarks.json`：新增城市及地点坐标。新增坐标于 2026-10-31 对照高德地点查询校验。营业时间、预约要求与景区接驳仍需出发前确认；预设不承诺实时票价或交通耗时。
- `frontend/src/data/inspiration.ts`：先完整解析预设，再写入草稿；缺失地点时显示错误，不会静默丢掉站点。

## 改名兼容性

用户可见品牌、页签、图标、AI 名称、导出署名和启动器标题改为 Waywise。GitHub 仓库、Docker Compose 项目、数据库和浏览器原有存储标识保留，避免改名导致数据丢失。历史文档中的旧名称保留作记录。

保存与分享的数据增加可选的城市字段；旧数据缺少城市时按起点就近识别已支持的城市。规划请求仍使用原有接口，地图与模型的配置方式不变。

## 本地验证

在 `frontend` 目录执行：

```sh
npm run test:inspiration
npm run test:origin-search
npm run test:route-display
npm run build
```

预设检查覆盖所有照片的完整地点解析、资产存在、城市交接、旧行程恢复、用户资料与对话保留，以及错误预设不改动草稿。

本次还通过浏览器将照片入口接到本机 FastAPI 与离线求解器，检查真实规划请求、首页助手、手机面板、图片解码和浏览器错误。离线验证不代表实时地图与交通接口的可用性；云端更新后需要再确认地图与在线规划。

### 出发地点搜索

出发地点优先调用同源 `/api/poi/online`，服务器通过已有的高德 Web 服务 Key 检索当前城市；失败时再尝试地图 SDK。Web 服务 Key 保留在服务器，接口不返回密钥或上游请求地址。接口拒绝、超时、坐标无效分别报错，仅真实空结果显示未找到。

当前城市决定检索范围和快捷词；连续查询只接受最后一次结果，切换城市、选定起点后忽略尚未完成的旧查询。可在 `backend` 目录运行 `python scripts/test_place_search.py` 验证服务器检索的错误处理与密钥隔离。

### 地图中的路线可靠性

距离矩阵来自高德不等于每一段都拿到了实际道路。地图逐段检查来源与 `approx` 标记：已确认路线用蓝色实线，未确认路段用灰色虚线，仅表示地点顺序，并显示查询失败原因和重试入口。回程同样检查。

缺失路段只按规划中的交通方式补查，使用当前城市；不会把失败的步行或公交查询换成驾车道路来画图。客户端补齐道路形状不修改后端时间、费用或地点顺序，估算数据继续标注。多日切换和重规划忽略旧请求的返回；只为已确认路线绘制流动箭头。

## 更新云端

在服务器的项目目录执行：

```sh
cd ~/lushu
git pull --ff-only
sudo docker compose up -d --build --force-recreate
```

更新保留现有 `.env`、访问密码、证书与数据卷。等待容器正常启动后刷新网页。
