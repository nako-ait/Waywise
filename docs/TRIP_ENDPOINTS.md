# 多城市交通与起终点

工作台右侧「出发地点」可搜索并选择酒店、学校、车站等地点，也可取地图中心。下方「行程终点」提供三种方式：

| 方式 | 规划与展示 |
| --- | --- |
| 返回起点 | 保留原有往返行程行为 |
| 最后一站结束 | 最后一站停留完成即结束，无额外回程、费用或折线 |
| 到指定地点结束 | 必须先搜索或取地图中心选定终点；终段参与排序、截止时间、交通选择和费用统计 |

多日行程前几天仍从同一个起点出发并返回，以上结束方式只用于最后一个实际排出的游览日。暂不支持逐天换住宿或跨城市交通规划。若没有可执行的游览日，显示未排入原因，不虚构到达终点的时间。

终点在地图用绿色标记区分，时间轴提供到终点的导航。保存、分享、导入及导出长图保留终点含义。选择地点后搜索面板自动收起；手机可在「行程」标签设置。修改城市、终点、时间或偏好后需要重新编译。

## 城市与接口

规划与 AI 请求携带当前 `cityName`，公交/地铁查询不再固定为上海。缺少城市字段的旧请求通过坐标逆地理编码获得城市编码；查询失败时保留明确的估算标记，不默认当作上海。每次规划的城市上下文独立，结束或失败后恢复。

所有城市使用在线目的地搜索；在线失败时仅显示本城市预置地点。起终点搜索继续使用同源服务器接口，不把 Web 服务 Key 交给浏览器。公交与地图搜索的实例、缓存按城市区分，旧路线缓存通过版本号自然失效，无需删除数据库。

新增的请求字段：

```json
{
  "cityName": "杭州",
  "endMode": "custom",
  "endPoint": { "name": "杭州东站", "lng": 120.212, "lat": 30.291 }
}
```

`endMode` 可为 `return`、`last_stop` 或 `custom`；默认 `return`。旧 `hotel` 字段表示起点；响应保留 `returnLeg` 和 `returnTime` 名称以兼容旧代码，含义分别为当日终段交通和结束时间。`last_stop` 没有 `returnLeg`。每个 `PlanDay` 的 `endMode` 与 `endPoint` 明确说明当天如何结束。

排序沿用现有两种求解器：矩阵从起点出发的行保持不变，进入虚拟终站的列改为到指定终点的成本；自由结束时该列为零。终点不作为景点计数，实际终段仍查询真实终点坐标。备用求解器也比较两个景点的反向顺序。

## 验证

后端：`python scripts/verify_all.py`，新增 `test_trip_endpoints.py` 检查终点改变最优顺序、终段时间/费用、自由结束、多日规则、无可行路线、AI 保留设置、城市并发隔离与旧请求的城市识别。

前端：`npm run test:trip-endpoints`、`npm run test:inspiration`、`npm run test:origin-search`、`npm run test:route-display`、`npm run build`。新增检查覆盖旧存档、保存分享、终点变更提示、城市搜索、地图终段、导航与长图结束标注。

浏览器验证以本地真实离线后端计算杭州行程，检查终点必填、切换结束方式、终点导航、地图标记及手机布局。另于 2026-11-02 使用既有配置分别核验上海、杭州、北京的真实高德公交请求，均返回路线；不表示所有城市、时段及路线都可达。

云端按现有方式拉取代码并重新构建容器，无需修改 `.env`、访问密码、证书或数据卷。
